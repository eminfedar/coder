# AGENTS.md

VSCode-like code editor in terminal. Rust + ratatui + tokio. Elm Architecture (Model / Msg / Cmd / update / view). **Code comments and UI text are in English.**

## Running

```bash
cargo run [dir]          # opens cwd if no dir is given
cargo build              # dev
cargo test               # unit tests (core/buffer, services/git)
cargo clippy             # lint (kept warning-free)
```

Environment: `CODER_ASCII=1` uses ASCII instead of Nerd Font icons (activity-bar panel icons fall back to emoji, `Panel::ascii_icon`). `CODER_EXTENSIONS` overrides extensions dir (default `~/.config/coder/extensions`).

## Architecture (Elm Architecture)

Single unidirectional loop, `src/main.rs::run()`:

```
event / async result  ->  Msg  ->  update(model, msg) -> Vec<Cmd>  ->  cmd::execute -> Msg (via tx)
                                        |
                                     Model changes  ->  ui::view(frame, model)
```

- **Model** (`app/model.rs`): all state. Pure data, no IO.
- **Msg** (`app/msg.rs`): input events + async results. Only input to `update`.
- **update** (`app/update/`): takes `Msg`, mutates `Model`, returns side-effect `Cmd`s. Synchronous, no IO.
- **Cmd** (`app/cmd.rs`): description of side effect. `execute()` runs on tokio, sends result back as `Msg` via `tx`.
- **view** (`ui/mod.rs`): draws `Model` with ratatui. Read-only.

Rule: IO and async live only inside `cmd::execute`. `update` never blocks (exception: `ReplaceDone` reads open buffers from disk with short synchronous `std::fs::read_to_string`).

### Layout sharing
`ui::compute_areas(model, area) -> Areas` computes layout once; both `view` and mouse hit-testing (`update::handle_mouse`) use same `Areas`. Mouse coordinate mapping always goes through it.

## Core concepts

- **Focus** (`Editor` / `Terminal` / `Sidebar` / `SearchInput` / `GitCommit` / `Find`): target of keyboard events. `keymap::resolve` branches on focus. `GitCommit` = commit-message input in git panel. `Find` = editor-embedded find/replace widget.
- **Tab**: open file = `Buffer` + `Highlighter` + `diff_mode`. `active_tab: Option<usize>`. `diff_mode` (opened from git panel) appends `(diff)` to tab title (`Tab.title()`) and paints line backgrounds in editor. Same file can open as two separate tabs, normal + diff: `tab_index_for` matches only **non-diff** tab (normal open never hijacks diff tab), `diff_tab_index_for` matches diff tab; `all_tabs_for` returns all tabs of a file (HEAD/save/replace updates apply to all). When new tab opens, highlighter set to active theme (`FileLoaded` → `set_theme(current_theme_name())`), so files opened after theme change color correctly too.
- **Config (persisted preferences)**: theme and settings written/read as TOML via `services::config`. On startup `Model::new` → `config::load()` + `apply_config()`. When theme or setting changes (`apply_theme`/settings toggle — keyboard nav, Enter, mouse) `Cmd::SaveConfig(model.config_snapshot())` sent.
- **Tab identity**: `Tab.id` is a process-unique stable id. Anything that resolves later (LSP `Token = (tab id, version)`, highlight jobs, `DialogAction::CloseTab`/`SaveAs`, tab context menu, `PendingFormat`, find matches) stores the id and resolves it with `Model::tab_by_id` — an index can name a different tab by then.
- **Highlight cache**: keyed by `(Tab::id, buffer.version)`; jobs carry an O(1) `Rope` clone (flattened on the worker thread). `refresh_highlight()` called before render. When you change buffer externally (`ReplaceDone`, external reload, closing tab) call `model.invalidate_highlight()` — else goes stale (new buffer resets to version 0). `invalidate_highlight()` also resets git-mark cache.
- **Change-gutter cache**: `Model.active_git_marks` (line → `GutterKind`), `active_git_marks_key = (tab, version)`. `refresh_git_marks()` called before render (main loop), comparing live buffer against `Tab.head_text` (HEAD content) via `gutter_marks` — pure, no IO. For diff tab also fills `Model.active_deleted` via `deleted_blocks`. `head_text` loaded async (`Cmd::LoadHeadText` → `Msg::HeadTextLoaded`): refreshed for all open tabs when file opens and on every `GitStatusLoaded` (HEAD may have moved after commit/revert).
- **Buffer selection**: `anchor: Option<Cursor>`. `pre_move(extend)` — if extend true and no anchor, puts anchor at cursor. `set_cursor(c, extend)` used for mouse selection.
- **DragTarget**: `SidebarBorder` / `TerminalBorder` (resizing) / `EditorSelect` (mouse text selection) / `Scrollbar` (scrollbar thumb drag). Set on `Down`, cleared to `None` on `Up`.
- **Language extensions / LSP** (`Model.extensions`, `Model.lsp`, `Model.diagnostics`, `Model.completion`, `Model.pending_format`): `extensions` is `ExtensionRegistry` loaded once in `Model::new`. `lsp: LspState` holds `sessions` (language id → `LspHandle`), `starting`, `initialized` sets. Each running server is one async owner task (`services::lsp::start`, the `pty.rs` pattern) that Model reaches through handle's `to_server` channel — routed via `Cmd::LspSend` so `update` stays IO-free. Results come back as `Msg::Lsp*`. **Staleness** guarded everywhere by `Token = (tab, buffer.version)` (same idea as highlight cache): completion/format responses whose token no longer matches buffer are discarded. **UTF-16**: LSP positions count UTF-16 code units; rope uses char indices. Convert only in `update` via `Buffer::char_col_to_utf16`/`utf16_to_char_col`/`lsp_pos_to_char` (unit-tested with emoji) — never in async task.

## Features (implemented)

- **Language extensions (LSP + formatter + linter)**: per-language support declared as TOML manifest at `~/.config/coder/extensions/<name>/extension.toml` (`$CODER_EXTENSIONS` override) plus built-in defaults for Rust (`rust-analyzer`/`rustfmt`) and Python (`pyright-langserver`/`black`). Manifest lists `[[languages]]`, each with `extensions`, `[languages.lsp]` server, optional `[languages.formatter]` (stdin→stdout) and `[languages.linter]`. User installs binaries; editor orchestrates. Extensions panel (`ui/sidebar/extensions.rs`) lists installed extensions + capabilities and running servers (status glyph + diagnostic count).
  - **Diagnostics**: `textDocument/publishDiagnostics` → `Msg::LspDiagnostics` → `lsp::store_diagnostics` converts UTF-16 ranges to char cols, stores in `Model.diagnostics[path]`. Rendered in `ui/editor.rs`: severity-colored line number + colored underline squiggle (`overlay_diagnostics`, drawn before selection overlay); diagnostic under cursor shows in status bar (`Model::diagnostic_at_cursor`). Documents synced full-text: `didOpen` on `FileLoaded`/`LspInitialized`, **debounced** `didChange` (`edit()` → `Cmd::ScheduleDidChange` → `Msg::DidChangeDue`, sent only if buffer version still matches — so typing pauses coalesce), `didSave` on `FileSaved`, `didClose` when last tab of file closes.
  - **Autocomplete**: auto-triggered while typing identifier / after `.` (and `Ctrl+Space`); `lsp::request_completion` flushes current text then requests `textDocument/completion`. **Client filters, not server**: rust-analyzer (like most servers) returns every candidate at position and expects client to match against typed prefix — `filter_items` scores each item's `filterText` in tiers (exact-case prefix → case-insensitive prefix → substring → subsequence, non-matches dropped) and breaks ties with server's `sortText`. Filtered list opens `Model.completion` (guarded by token *and* caret: `LspState.completion_request` stores the request's `(Token, Cursor)`; a response opens the popup only if it is the latest request and the caret hasn't moved — a click moves the caret without bumping the version). Any mouse press dismisses the popup, clears `completion_request` and cancels a pending auto-trigger (`input::mouse`); `Esc` clears `completion_request` too. Popup is **editor sub-mode**, not `Focus`: while `model.completion.is_some()`, `update` routes keys to `lsp::completion_key` first (Up/Down select, Enter/Tab accept, Esc dismiss; identifier keys/Backspace fall through and re-request; other keys dismiss). Accept selects typed prefix `[anchor, cursor]` and `insert_str` replaces it.
  - **Formatting**: `Ctrl+Alt+F` (`Action::Format`) or format-on-save. `lsp::request_format` prefers LSP server (`textDocument/formatting` → `Msg::LspFormatEdits` → `apply_text_edits`, applied end-first as one undo step), else standalone formatter tool (`Cmd::RunFormatterTool`, stdin→stdout → `Msg::FormatterOutput`). Format-on-save **defers** `WriteFile` until edits apply (`Model.pending_format.save_after`); formatter failure still writes original text so save not lost. Standalone linters run on save for LSP-less languages (`Cmd::RunLinterTool`, parsed as `line:col: message`).
- Preview tab (VSCode-style): `↑`/`↓` in the Files panel previews the selected file, in the Git panel the selected change's diff (or a history commit's patch) — `sidebar_nav::preview_selection` → `tabs::preview(PreviewKey)`. Focus stays in the sidebar. `Tab.preview` marks the tab (italic title); `tabs::place_tab` swaps a new preview into the existing clean preview tab instead of pushing another (LSP `didClose` for the displaced file). In-flight loads are counted in `Model.preview_loads`; `take_preview_load` (in `FileLoaded`/`CommitDiffLoaded`) drops a load the user already arrowed past, only `Model.pending_preview` becomes the tab. `Enter`/`→` (`activate_selection` → `open_path`/`open_diff`/`open_commit_diff`) clears `preview`, cancels a pending preview of the same key, and moves focus to the editor; editing (`editor::mutate`) also clears `preview`. Search results preview too (arrows or click), at the match line (`preview_at` → `pending_goto`). **A click in any sidebar panel never takes focus**: clicking a file row (Files), change/commit row or file icon (Git), result (Search) or an Edit row (Settings, via `config_file`/`keybindings_file`) previews it and keeps `Focus::Sidebar`, so ↑/↓ keep driving the panel; only Enter/→ or clicking the editor moves focus there. Mouse wheel over the sidebar only moves the selection (no preview).

- Session persistence (`services/session.rs`, `app/update/session.rs`): reopens a workspace's tabs — cursor/scroll, and unsaved ("dirty") content — when `coder` is relaunched in the same folder, including after a crash or kill (not just a clean quit), and even for a file deleted outside the editor since (it keeps showing as unsaved). Stored **globally**, one TOML file per workspace at `~/.config/coder/sessions/<dev>-<ino>.toml` (`$CODER_SESSION_DIR` override) — keyed by the root directory's `(dev, inode)`, not its path string, so a same-filesystem `mv`/rename of the workspace doesn't lose the session (a cross-filesystem move, or a copy, gets a fresh inode and starts a new session; documented, not fixed). `root_key` is `#[cfg(unix)]`; non-Unix targets (Windows) key by an FNV-1a hash of the canonical path instead, so there any rename starts a new session.

  - **Restore** (`update::restore_session`, called once from `main::run` before the event loop, after `Cmd::ScanDir`/`LoadGitStatus` are queued but before an explicit CLI file argument is opened — the latter dedupes against an already-restored tab via `tab_index_for`/`pending_session_restore` instead of opening a second copy): a tab whose content is already known — untitled, or a small dirty file — is rebuilt synchronously, working even if the file no longer exists on disk (nothing touches disk for it, so a deleted file just keeps showing dirty). Everything else (a clean file, or a large dirty file stored as a diff) is queued in `Model.pending_session_restore` (keyed by path) and read the ordinary way (`Cmd::ReadFile` → `Msg::FileLoaded`); when it arrives, `apply_hunks` reconstructs the dirty text over the freshly-read disk content (falling back to opening it clean + a toast if the base changed too much to apply — never a silent corruption), and the stored cursor/scroll is clamped onto the actual line count. Which tab ends up focused is tracked by **key**, not index (`SessionSnapshot.active`, a path or `"untitled:<id>"` — generated tabs are never persisted, so a plain position would drift): `Model.session_active_path` holds the pending target so whichever async file happens to finish loading *last* doesn't win the focus race (`Msg::FileLoaded`'s `restoring_to_other` guard only lets the matching path claim `active_tab`; `Msg::FileLoadFailed` releases the guard too, so a 404 on the target file doesn't wedge every later open).

Deliberately **not** per-file and **not** merged — a real fix (per-file generations, or a 3-way merge using the same hunk machinery) is future work, not in this pass.
  - Deliberately out of scope for this pass: undo/redo history is never persisted (only the current text/cursor).

- Data-safety rules (keep them when touching these paths):
  - `Msg::FileSaved` carries the written text; a tab is marked clean only if it still holds exactly that (typing during an async save stays dirty).
  - A dirty tab is never dropped or overwritten by async events: `ReplaceDone` reloads only clean tabs (toast for dirty ones), `GitStatusLoaded` demotes a dirty diff tab instead of closing it, `PathDeleted` keeps dirty tabs, `FileLoadFailed` never turns a dirty tab into a notice, Open Folder refuses while any tab is dirty.
  - Format-on-save always writes: a dead LSP server (`remove_server`) or `FORMAT_TIMEOUT` (`tick`) falls back to `abandon_format`, which saves unformatted.
  - A duplicate `FileLoaded` for an already-open (non-diff, non-preview) path focuses the existing tab instead of opening a second one (no double `didOpen`).
  - The commit message box is cleared only on `Msg::GitCommitted`.
  - The main loop redraws only after a message or tick work (1s idle heartbeat).

The focused button swaps its fg/bg (`button_style`) and `Enter` presses it (`git_zone_activate` → `git_button`, disabled buttons are no-ops). On the change list: `↑`/`↓` select, `Enter` opens the diff, `a` stages / unstages the selected file (`git_toggle_stage`), `r` reverts it after a confirmation dialog (`git_revert_entry`; a staged entry must be unstaged first). `GitZone::Message` is the one zone that also sets `Focus::GitCommit`, so `set_git_zone` keeps the two in sync — mouse clicks, `Esc` and `select_panel` all go through it.
Git commit input: `Tab` into it or click it (`Focus::GitCommit`) · type · `Enter` inserts newline · `Tab` to the Commit button and `Enter` (or click it) to commit · `Esc` back to the change list.

## When making changes

- New `Msg` -> add variant to `msg.rs` + match arm in `update/mod.rs`.
- New side effect -> `Cmd` variant in `cmd.rs` + `execute` arm; never do IO inside `update`.
- New shortcut -> `Action` in `keymap.rs` + `resolve_*`; handle in `update::apply_action`.
- Adding mouse target: get layout from `compute_areas`, add field to `Areas`. If you change render row layout, also update corresponding `*_row_at` hit-test offsets (`ui/sidebar/`).
- After changing buffer externally, call `invalidate_highlight()`.
- LSP: talk to server only through `Cmd::LspSend` (never IO in `update`). Convert LSP UTF-16 positions to/from char columns only in `update` via `Buffer` helpers; guard every response with its `Token`.
- **Keep this file current**: when architecture, directory map, or feature changes, edit AGENTS.md too.
